# Curated Directory of HackerNews Clients

Curated directory of Hacker News clients across web, mobile, desktop, terminal,
and extensions. Built as a static Astro site and published at
https://hackernews.hn.

## Features

+ Filter and search by platform, price, status, and open-source
+ Client detail pages with links, tags, and metadata
+ JSON-backed content with schema validation
+ Static output for fast hosting

## Project Structure

+ `src/pages/` - Listing and client detail pages
+ `src/lib/clients.js` - Client data loader
+ `data/clients.json` - Curated client entries
+ `data/taxonomy.json` - Allowed platforms, tags, pricing, status
+ `schema/client.schema.json` - JSON schema for client entries
+ `scripts/validate-clients.mjs` - Data validation script

## Requirements

+ Node.js `~24.8.0`
+ npm `~11.6.0`

## Development

```bash
npm install
npm run dev
```

## Build and Preview

```bash
npm run build
npm run preview
```

Build output is written to `docs/` (see `astro.config.mjs`). The postbuild step
rewrites asset paths so the site can be served from a subdirectory and adds
`docs/.nojekyll` so that GitHub Pages doesn't try to process the project using
Jekyll.

## Data Updates

Validate client entries before submitting changes:

```bash
npm run validate:data
```

## Using the `tools` Branch

The 3 branches, `master`, `gh-pages`, and `tools` are kept separate beause each
one's intent is different.

The `master` branch contains the actual source code of the project.

The `gh-pages` branch contains _only_ the artifacts generated from the `master`
branch, as documented in the sections above. Hence it contains only the
`./docs/` directory produced by the build step; specifically, it doesn't contain
_any_ of the original source code from the master branch.

The `tools` branch contains the configuration and log files used and/or
generated by the tools used for development, but which are _not_ necessary for
building the source code and producing the artifacts. Currently, these tools
include the Codex CLI and TaskWarrior.

It's important to realize that both branches, `gh-pages` and `tools`, are
derived from the `master` branch; that is, they contain commits that are
descendants of the commits on the master branch.

### Workflow to Use the Tools

For making any change to the `main` branch which requires use of the
non-essential tools (Codex, etc.), follow this procedure.

Checkout the `tools` branch. Use the tools to create, update, or delete files in
the source code. This usage of tools will produce log files, or need changes to
the tools' configurations, etc. Stash these tools-specific changes.

Switch to the `master` branch. Commit the changes to the `master` branch. Run
the build commands which will add, update, or delete content from the artifacts
(e.g. the `./docs` directory).

Switch to the `gh-pages` branch and merge the `master` branch into it. Then use
`git rm` to delete all files and directories except the `./docs` directory. Then
use `git add ./docs` to update the contents of the `gh-pages` branch.

Finally, switch to the `tools` branch and merge `master` branch. Then unstash
the file contents stashed earlier, and commit those chnages to the `tools`
branch.

At this point all branches are ready to be pushed to their respective remotes.

```bash
git switch tools

# ... use the tools to make changes to the project source code.

git stash -p # Stash away the changes that are tools-specific

git switch master

git add ... # Add the source-code changes to the master branch
git commit ... # and commit those changes to the master branch

npm build # Produce the artifacts from the source code

git switch gh-pages
git merge master
# Delete all files and directories except ./docs and ./.git
find . -mindepth 1 -maxdepth 1 ! -wholename ./docs -a ! -wholename ./.git -exec rm -rf {} +
git add -a     # Add what remains
git commit ... # and commit to the gh-pages branch

git switch tools
git merge master
git stash pop
git add ...
git commit ...

git push ...
```
